Hollywood for Windows 1.9 - November 4, 2026

Built and tested on Windows 11 using the Windows .NET Framework compiler.
Both desktop and terminal regression suites pass. They cover all 23 widgets,
original Classic random splitting/rebuild behavior, monitoring calculations,
pinning, old/new layouts, process identity/history, network selection, weighted
geometry, tiny windows and Studio restoration after Classic activity.

New pane-editor checks cover all widget choices, both split orientations,
replacement and swapping existing widgets, nested and root-level removal,
expanding sibling groups, selected-pane identity, automatic pinning, timed and
manual shuffle stability, one-pane and 20-pane limits, undersized split rejection,
20-step bounded undo, current monitoring preferences surviving undo, saving and
loading, failed-load atomicity, mode switching and history reset on layout load.
Editor rendering is checked down to a one-cell window. E/U are inactive in Classic.

Windows sampling took about seven seconds to publish the initial sample on this
host. The regression suite now allows up to 20 seconds for that first sample;
the application's sampling and Classic behavior were not changed.

Native desktop integration uses a private Windows desktop, without moving the
user's windows. The actual Pane, Action and Widget dropdowns are exercised:
column/row splits, replacement, swapping, pane selection, removal, undo button,
U shortcut, cancellation, divider sizing, small-window recovery, save/load and
F2 mode restoration. Saved layouts are compared exactly. Dialog and completed
canvas screenshots were inspected. The app exits cleanly.

Native terminal integration uses Windows ConPTY. It exercises E/R/H/V/X/U,
arrows/Home/End/Enter, editor and canvas resizing, B divider sizing, W/L save/load,
undo reset after loading another layout, Classic isolation and restoration.

Ubuntu integration uses the existing Python launcher in an actual Linux PTY.
Raw output is captured before Windows console interpretation. It exercises the
same editing workflow, save/load, Classic restoration and resizing at 209x54,
45x12, 121x30 and 240x64. Parsed output verifies every cell of the custom pane
borders and the pane headers at every size. Ctrl+C exits cleanly and restores
the exact previous Ubuntu tty settings. The installed alias is also checked.

The core Scene.cs random layout engine, original widget implementations,
monitoring collectors and Ubuntu launcher are unchanged from version 1.8.1.
The editor shares one state/controller across the two native frontends and uses
the existing layout formats, so it does not migrate or rewrite user profiles.

The ZIP is extracted and every packaged file is byte-compared with the release
tree. Installation backs up replaced program files and checks installed hashes.
Existing user layouts are stored separately and are not overwritten.

Hardware and platform limits: live testing used one Windows 11 machine and its
Ubuntu distribution. Other Windows versions, GPU vendors and multi-GPU hardware
were not available for live validation. Protected process data may be unavailable;
sampling delays exclude the time Windows takes to collect counters and logs.
